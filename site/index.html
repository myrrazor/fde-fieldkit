FDE Tools

Eight local field utilities for the work between “we got the dump” and “the customer can trust the result”: inspect, sanitize, synthesize, compare, report, check drafts, watch agent traffic, and check an AI workload spec without sending customer data to a hosted service.

01 / Inspect unfamiliar data

xray

Profile schema, inferred types, null rates, summary statistics, outliers, and PII flags for CSV, TSV, XLSX, JSON, and JSONL files. Use --html for a redacted report or --json for machine-readable output. Raw values require an explicit CLI opt-in.

Read the xray docs →

02 / Remove detected PII before sharing

scrub

Replace detected emails, phones, SSNs, cards, IPs, names, and secrets with realistic fakes. Sparse recognized matches are covered and residual recognized PII stops the run. Detection still requires output review.

03 / Build credible demo data

mimic

Learn column types, category pools, and distributions from a sample, then generate as many rows as you need from an editable YAML specification. PII columns use independent Faker providers without storing source-value fingerprints. The same seed produces the same output; inspect it before sharing.

Read the mimic docs →

04 / Explain what changed

datadiff

Compare two dumps for added or dropped columns, type drift, keyed row additions, removals and edits, plus value drift by column. It detects a key when it can; use --key customer_id to override it. Reports redact raw row/category values unless the CLI explicitly opts in.

06 / Check the draft before it ships

tell

Run ten local stylometric checks on a draft and keep those signals separate from any remote classifier score. Neither establishes who wrote the text. Remote checkers need vendor keys and an explicit --remote run; the CLI names every destination before text leaves the machine. The default stays offline. Use unslop to strip deterministic slop patterns.

Read the tell docs →

07 / Observe agent network access

netwatch

Launch Codex, Claude Code, or another command through local HTTP and SOCKS5 proxies. Netwatch records destination metadata, groups common services, and can enforce a deny-by-default host, IP, port, and protocol policy before opening an upstream connection.

The local control room compares sessions and sources, launches supervised noninteractive commands, discovers agents, attaches by PID, edits and tests policy, filters the traffic ledger, and exports reports. Interactive agents still run in their terminal while the dashboard follows the session.

Coverage stays visible beside the totals. HTTPS content remains encrypted, attachment is observation-only, and DNS, UDP/QUIC, and sockets that bypass the proxies are not counted.

08 / Check an AI workload spec

AWCP

Validate a WorkloadSpec, fingerprint its config and prompts, list declared tools with approval and risk, diff two versions, and score a recorded golden suite against the spec's gates. YAML or JSON. Local only: it does not call a model, run promptfoo, or talk to a control plane.

Read the awcp docs →

Install and run

Add the tool, then check a spec 
fieldkit plugin add awcp
fieldkit awcp check workload.yaml

Example uses

README commands

uv run fieldkit awcp diff examples/awcp/support-ticket-triage.yaml examples/awcp/support-ticket-triage-v2.yaml
uv run fieldkit awcp eval examples/awcp/support-ticket-triage.yaml --suite examples/awcp/support-triage-golden.yaml

Operating constraints

Built for the awkward middle.

  • Keep it local Fieldkit runs locally by default. Tell needs vendor keys and an explicit remote run, and it names each destination first. Netwatch relays only traffic requested by the command you supervise and stores metadata locally.
  • Show the work Commands can produce inspectable JSON, markdown, and HTML artifacts instead of opaque claims.
  • Repeat exactly Deterministic replacements and seeded generation make demos and checks reproducible.
  • Stay honest awcp checks specs and scores recorded golden cases. It does not call a model, run promptfoo, or stand in for a delivery control plane.

Practical questions

Before you use it

What is FDE Tools?

It is the index for the Fieldkit toolkit: one fieldkit core you install once, and eight tools you add with fieldkit plugin add.

What does it cost?

This site has no payment flow, subscription, or hosted account. Review each repository’s maturity and license status before adopting it.

Where does my data go?

Fieldkit runs locally by default. tell contacts remote detector services only when you set their vendor keys and explicitly authorize a remote run, and it warns before any text leaves the machine. Netwatch is a user-requested relay: it opens the destinations requested by the supervised command, applies your policy, and stores metadata locally. This website has no upload form, analytics, cookies, or embedded third-party content.

How do I delete data or get support?

The site stores nothing to delete. Remove files created by the CLI from your own machine, and use the fde-fieldkit repository for source, issues, and project updates.

Fieldkit is free and built in the open. If it saved your Friday afternoon, you can buy me a coffee, or star the repo so the next engineer with a mystery CSV can find it.
