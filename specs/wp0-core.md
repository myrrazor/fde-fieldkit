## core/io.py

```python
@dataclass
class LoadedTable:
    df: pd.DataFrame
    fmt: str                 # "csv" | "tsv" | "xlsx" | "json" | "jsonl"
    source: str              # filename or "<buffer>"
    warnings: list[str]

def detect_format(filename: str | None, sample: bytes) -> str
def load_table(src: Path | BinaryIO, *, filename: str | None = None,
               fmt: str | None = None, sheet: str | None = None) -> LoadedTable
def write_table(df: pd.DataFrame, dest: Path | IO, fmt: str) -> None
def formula_safe_value(value: object) -> object
```

- Detection: extension first, else sniff the first ~4KB (xlsx magic `PK`, `[`/`{` for
  json, one-json-object-per-line for jsonl, tab count vs comma count for tsv/csv).
  Unknown → ValueError with a helpful message.
- Everything is read **as strings** (`dtype=str`, `keep_default_na=False` then map
  `"" -> pd.NA`; also treat `N/A`, `null`, `NULL`, `None`, `nan` literals as NA).
  Typing is `core/types.py`'s job, not the loader's.
- json: a top-level list of objects via `pd.json_normalize` (one-level dotted
  flattening). A top-level dict → ValueError telling the user we need a list of records.
- xlsx: openpyxl, first sheet unless `sheet=`. Cell values stringified; dates via
  `str(cell.value)`. Collect a warning if any merged cells are seen. The total input
  and XLSX logical/uncompressed contents each use the authoritative 50 MiB dataset cap.
- write_table supports csv/tsv/xlsx/json/jsonl (used by scrub/mimic to write output in
  the input's format). CSV, TSV, and XLSX cells and headers that spreadsheet software
  could execute (`=`, `+`, `@`, tab, carriage return, or non-numeric `-`) are prefixed
  with an apostrophe. JSON and JSONL are unchanged.

## core/types.py

```python
class ColType(StrEnum):
    INTEGER; FLOAT; BOOLEAN; DATETIME; DATE; CATEGORICAL; ID_LIKE; TEXT; EMPTY

def infer_column(s: pd.Series) -> ColType
def infer_types(df: pd.DataFrame) -> dict[str, ColType]
def coerce(df: pd.DataFrame, types: dict[str, ColType]) -> pd.DataFrame
```

- A column is a type when ≥95% of its **non-null** values parse as it. All-null → EMPTY.
- Order of checks: EMPTY, BOOLEAN (true/false/yes/no/0/1 — but 0/1 only when the value
  set is exactly {0,1}), INTEGER (allow thousands separators), FLOAT, DATE (no time
  part), DATETIME, then ID_LIKE, CATEGORICAL, TEXT.
- ID_LIKE: all values unique AND (monotonic-ish integers OR all values match one
  uniform pattern — same length/shape like `CUST-0042`).
- CATEGORICAL: distinct/nonnull ≤ 0.05 or distinct ≤ 20 (and not boolean).
- Date parsing: try a small explicit list of common formats (ISO, %m/%d/%Y, %d/%m/%Y,
  %Y-%m-%d %H:%M:%S, ISO8601 w/ T) — no dateutil fuzzing.
- `coerce` returns a typed **copy** (errors="coerce"), leaves TEXT/ID_LIKE/CATEGORICAL
  as strings.

## core/pii.py

```python
class PIIKind(StrEnum): EMAIL; PHONE; SSN; CREDIT_CARD; IP; NAME; SECRET

@dataclass
class PIIMatch:
    kind: PIIKind; start: int; end: int; value: str

@dataclass
class PIIColumnReport:
    kinds: dict[PIIKind, float]      # kind -> confidence 0..1 (only kinds ≥ 0.5)
    hit_rate: float                  # fraction of sampled non-null values with any hit
    samples_masked: list[str]        # up to 3, e.g. "j***@a***.com"

def scan_text(text: str) -> list[PIIMatch]           # free text / log lines
def scan_column(s: pd.Series, *, column_name: str = "", sample_size: int = 500) -> PIIColumnReport
def scan_dataframe(df: pd.DataFrame) -> dict[str, PIIColumnReport]
```

Validation beats regex-only — false positives are the #1 complaint with tools like this:
- EMAIL: regex + must have a dot in the domain.
- PHONE: 10–15 digits after stripping `()+-. ` and optional leading country code;
  reject if it also validates as SSN-shaped 9 digits in `nnn-nn-nnnn` layout.
- SSN: exactly `nnn-nn-nnnn` or 9 bare digits, area != 000/666/9xx, group != 00,
  serial != 0000. Bare 9-digit form only counts when the column name hints at it
  (contains "ssn" or "social").
- CREDIT_CARD: 13–19 digits (spaces/dashes ok) AND passes Luhn.
- IP: 4 octets each 0–255.
- SECRET: known prefixes (`AKIA`, `sk-`, `ghp_`, `gho_`, `xoxb-`, `xoxp-`,
  `-----BEGIN`) or (length ≥ 20, one token, Shannon entropy > 4.0 bits/char).
- NAME: value (or each of its 1–2 words) hits the bundled top-1000 first/last name
  lists (`core/data/*.txt`, lowercase one-per-line — generate them from faker's
  en_US providers in make_fixtures.py, dedup, commit). Base confidence 0.4; +0.3 when
  column_name contains name/first/last/full. Only kinds ≥ 0.5 get reported, so bare
  dictionary hits without a column hint stay out.
- Column confidence for other kinds: fraction of sampled non-null values that
  validate. scan_column samples up to sample_size values evenly.
